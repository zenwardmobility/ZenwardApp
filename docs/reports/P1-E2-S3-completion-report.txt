12-15. DRIVER PROFILE / ACTIVE LIST / DETAIL / HISTORY — IMPLEMENTATION
--------------------------------------------------------------------------------
driver_get_profile: own-data-only projection of the caller's Driver row +
  organization name. current_driver_id(org) resolution; ZW002 if none.

driver_list_active_trips: joins trip_assignments (current, ended_at IS
  NULL) -> trips -> passengers (display_name only) -> vehicles (label/
  status only, LEFT JOIN since a vehicle is optional), scoped to the
  caller's own Driver id in the given org. Ordered by scheduled_pickup_at.

driver_get_trip_detail: organization derived from the Trip itself (never a
  parameter). Requires a CURRENTLY active trip_assignments row — a
  historical one is never sufficient. Assembles passenger identity/phone,
  the Trip's own assistance_notes/instructions snapshot, vehicle summary,
  and driver_visible notes (jsonb_agg of explicit jsonb_build_object
  values) in one query.

driver_list_trip_history: only ENDED (ended_at IS NOT NULL) assignments,
  bounded date range (default trailing 90 days, hard cap 180 days),
  trip_outcome populated only for a terminal Trip state.

35. THE current_driver_id() GAP — FULL ACCOUNT (referenced above; detailed here)
--------------------------------------------------------------------------------
While writing driver_read_authorization_tests.sql's inactive-Membership
test (DETAIL-6, work item §31's required "critical test"), the test failed
unexpectedly: an inactive-Membership Driver still received a successful
Trip detail response. Root cause: current_driver_id() (a P1-E2-S1 helper,
already committed at the time this gap was found) resolved auth.uid() to a
Driver row using only `drivers.status = 'active'` — it never cross-
referenced the underlying `memberships` table's status or role AT ALL.
This meant a Driver whose Membership was revoked but whose `drivers` row
remained active kept full authority, through EVERY function built on
current_driver_id() — not just this phase's read RPCs, but also
is_driver_assigned_to_trip and every P1-E2-S2 mutation RPC's authorization
chain. is_org_member/has_org_role already checked membership status
correctly; current_driver_id did not, and nothing before this phase's
specific test happened to exercise that exact combination.

Fixed via a new append-only migration (20260831110300, since the
defining migration is historical and immutable) that adds an EXISTS check
against an active, role=driver Membership row, alongside the existing
drivers.status check. Signature/return type unchanged, so every caller was
corrected automatically. Full regression re-run immediately after: all 13
SQL suites (156 assertions at that point) plus the concurrency test — zero
regressions, and the originally-failing DETAIL-6 test now passes. Recorded
as ZD-100. This was reported and fixed within this phase rather than
deferred, consistent with this project's established practice.
