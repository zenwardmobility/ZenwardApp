9. DRIVER TODAY COMPOSITION
--------------------------------------------------------------------
`src/app/driver/page.tsx` is a Server Component. It re-derives
`requireDriverAccess()` (matching the existing pre-phase pattern —
cheap, and the parent layout has already guaranteed "ok" by the time
this page can render at all), then calls `driver_list_active_trips`
directly via the existing authenticated server Supabase client — no
`useEffect`, no client-side fetch-after-mount, no service-role key
(work item §30/§31/§32). The page filters/sorts the result into
"Today" (§13/§16 below), renders `DriverNextTripCard` for the
earliest trip and a list of refined `DriverTripCard` rows (each
wrapped in a plain `next/link` `<Link>`, not a client `onClick`, so
no additional Client Component boundary was needed) for the rest,
and falls back to the empty or error state as appropriate. No
`"use client"` was added to the page or any new component beyond
what already existed (`DriverLayoutClient` was already a Client
Component; nothing new was added to the client bundle for Today
itself — work item §31).

15. CURRENT/NEXT-TRIP DERIVATION
--------------------------------------------------------------------
No new Trip state was created. "Next Trip" = the earliest-by-
`scheduled_pickup_at` row among today's active trips (a UI grouping,
computed in the page, not stored anywhere). "Later Today" = the
remaining today-scoped rows, in ascending order. See §16 for the
"today" filter itself.

--------------------------------------------------------------------
16. TIME FORMATTING
--------------------------------------------------------------------
`formatTripTime()`/`formatLongDate()` use the standard `Intl` API
with no explicit `timeZone` override — the runtime's own local
timezone, since no per-organization or per-request timezone
architecture exists anywhere in this product yet (confirmed by
inspection: no timezone field in schema.md/lifecycle-model.md, no
prior phase built one). No timezone conversion architecture was
invented (work item §19) — documented as ZD-116, including the known,
bounded cosmetic limitation this implies near local midnight. "Today"
grouping (`isSameLocalDay`) uses the same runtime-local basis. A
trip with a null `scheduled_pickup_at` (optional at creation) is
excluded from Today entirely — it isn't hidden from the product, it
simply has no unambiguous "is this today" answer and would surface
on the (not-yet-built) Trips screen instead.
