4. SEEDING ERRORS FOUND AND FIXED (before this session's own
   summarized portion begins, carried into this report for
   completeness)
--------------------------------------------------------------------
Three real SQL errors were found and fixed while authoring the seed
block (all confirmed via the exact `psql` error text, all fixed with
targeted, reviewed edits, not blind retries):
  1. An invalid hex digit (`h`) used as a fixture-tag letter — fixed
     to `f` (the one remaining unused single hex letter after
     a1-e1 were confirmed already used elsewhere in the file).
  2. Missing `::uuid` casts on facility-id literals inside a
     `select ... union all select ...` trips block — Postgres does
     not auto-infer target-column types there the way it does for a
     plain `insert ... values (...)`. Fixed with explicit casts.
  3. An invalid `requester_relationship` value (`'facility'`) — the
     real CHECK constraint only permits `('self', 'family',
     'caregiver', 'facility_coordinator', 'other')`. Fixed to
     `'facility_coordinator'`.
After these fixes, `supabase db reset` succeeded cleanly and a direct
`psql` count query confirmed every fixture count matched the intended
design exactly.
