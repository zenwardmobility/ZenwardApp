37-40. DRIVER TRIPS (before/discrepancies/corrections/final)
--------------------------------------------------------------------
Before: a REAL bug, not a style gap — TWO separate "TODAY" headers
rendered whenever more than one trip fell on the same day (the featured
trip was pulled entirely out of the date-grouping loop and given its
own always-present header). Root-caused directly in `page.tsx`: `const
[featured, ...rest] = scheduled` excluded the featured trip from the
`rest` array the grouping loop iterated over, so `rest`'s own grouping
never re-created a group the featured trip's OWN separate section had
already claimed for that date. Corrections: rewrote to group EVERY
scheduled trip (including the featured one) by calendar day first, then
render the featured trip's richer `DriverNextTripCard` inside its own
group's single shared section header — every other same-day or
later-day trip uses the compact `DriverTripCard` under the correct,
non-duplicated header. Final: screenshot-confirmed — exactly one "TODAY"
header now covers all 3 same-day fixture trips, one "TOMORROW" header
covers the 4th. **VISUAL READY.**

75. COMMERCIAL-QUALITY ASSESSMENT (work item §64 — answered plainly,
    not generously)
--------------------------------------------------------------------
Does Zenward still look like a template? No — the dark Care Navy
sidebar, the restrained amber Assurance system, and the real operational
density across Today's Operations/Dispatch are now visually distinct
from a generic Tailwind admin starter kit, which the light sidebar
genuinely did resemble before this phase.

Does any core page visibly look generated independently from the
others? No, materially less than before — the shared sidebar was the
single biggest source of that impression, and it is now identical
across all 4 Operations screens.

Does any core control look unfinished? The Trip Exceptions panel on
Trip Detail (its own extra vertical space vs. the reference's tighter
treatment) is the one remaining item that reads as slightly less
polished than its neighbors — real, honestly reported, not hidden.

Does any visible navigation imply functionality that does not exist?
No new instance was introduced this phase; the existing 9-item sidebar
was re-audited and remains truthful (§51).

Does Operations feel appropriate for all-day dispatcher use? Yes — dense
tables, a fixed grid window, no decorative whitespace; the fixes this
phase made (truncation, the missing attention metric) directly improve
this, they don't work against it.

Does Driver feel appropriate for one-handed use? Yes — single-column,
large touch targets, one dominant CTA per screen; the new Report Issue
button follows the same secondary-action sizing already established,
not a diagnostic-looking bolt-on.

Would a serious NEMT operator looking at these screens believe this is
a commercial product rather than a prototype? Closer than before this
phase, and honestly still not fully finished — the Passenger combobox
and the dark sidebar were the two most template-like tells, and both
are now addressed; a genuinely skeptical operator would still notice
the Trip Detail exceptions-panel density and the still-absent Driver
Availability concept (both openly documented here, not concealed).
