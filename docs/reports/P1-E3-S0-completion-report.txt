22. INTERNAL NEW TRIP ANALYSIS
--------------------------------------------------------------------------------
The most architecturally significant reference in the set. Confirmed via
direct migration inspection: `trips` INSERT is granted to `authenticated`
WITHOUT column restriction (unlike UPDATE, which was properly narrowed in
P1-E2-S1) — a raw client INSERT could set `state` to any value at
creation, bypassing the entire lifecycle model this project has otherwise
carefully protected. This is GAP-1, the top BLOCKING finding of this
phase. The screen's "Import request details" affordance additionally
requires GAP-2 (no atomic create-Trip-and-accept-Request mechanism
exists). Passenger search/creation is unaffected and already backend-
ready (Passenger has no lifecycle machine to protect). This screen is the
one BLOCKS SPECIFIC SCREEN item in the whole matrix.
