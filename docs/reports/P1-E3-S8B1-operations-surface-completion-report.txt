--------------------------------------------------------------------
8. TRIPS QUERY/FILTER/PAGINATION
--------------------------------------------------------------------
Server-side pagination via `.range()`, `TRIPS_LIST_PAGE_SIZE = 25`
rows/page — never an unbounded historical load. A real, found-and-fixed
bug in this module's own first draft: search and assignment filters
were initially applied as a client-side re-filter AFTER `.range()` —
this would have silently dropped matching rows outside the current page
and reported a wrong `totalCount`. Rewritten so every filter resolves
to a real database condition (a resolved Passenger-id set for search, a
resolved active-assignment-id set for assignment) BEFORE pagination —
one correct, correctly-counted query. A two-phase driver-name lookup
(the same discipline `dispatch-board.ts` established) scoped to exactly
the current page's Trip ids, never a broader per-org scan.
